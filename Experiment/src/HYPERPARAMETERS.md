# 超参数清单

本文件汇总 `motionedit` 中**所有可调量**：它们在哪、默认值是多少、改动后会发生什么。

阅读约定：

- **🔵 已实证** — 有实测数据支撑，不建议随意改动
- **🟡 经验值** — 合理但未做过敏感性分析，是调参的主要着手点
- **🔴 待定** — 尚未验证，很可能需要针对具体数据调整

---

## 0. 一分钟速查：最可能需要改的 5 个

| 想解决的问题 | 改什么 | 位置 |
|---|---|---|
| 求解太慢 | `adam_iters` 600 → 300 | `SolverConfig` |
| 结果没到位、误差偏大 | `adam_iters` 调大 / `adam_lr` 0.01 → 0.02 | `SolverConfig` |
| 动作偏离原风格太多 | `calibrate_ratios["prior"]` 0.3 → 0.6 | `SolverConfig` |
| 还有轻微脚滑 | `calibrate_ratios["contact"]` 0.4 → 0.8 | `SolverConfig` |
| 出现 ROM 越界告警 | `rom_growth` 20 → 50 | `LossWeights` |

## 1. 求解器 — `motionedit/solver.py` 的 `SolverConfig`

调用方式：`solve(seq, skel, target, cfg=SolverConfig(adam_iters=300, ...))`

| 名称 | 默认 | 状态 | 说明与调整建议 |
|---|---|---|---|
| `adam_iters` | 600 | 🟡 | 一阶优化迭代数。实测 300 次已基本收敛（误差 < 1.0），600 是留余量。**这是耗时的主要来源**，追求速度优先砍这里。 |
| `adam_lr` | 0.01 | 🟡 | 学习率。单位是"弧度/步"，0.01 ≈ 0.57°/步。调大收敛快但易振荡；若日志中 total 上下跳动则调小。 |
| `lbfgs_iters` | 60 | 🟡 | 二阶精修迭代数。收益递减明显，实测 25→40 提升有限。 |
| `lbfgs_lr` | 0.5 | 🟡 | 因启用了 strong-Wolfe 线搜索，此值影响很小。 |
| `max_rotation_deg` | 75.0 | 🟡 | **安全阀**：单关节相对参考的最大旋转。防止优化器"转出去再绕回来"得到数值等价但视觉崩坏的解。暖启动后实测最大仅 30.9°，未触发。若 notes 报"安全阀触发 N 次"，说明参数过激进。 |
| `max_translation_m` | 1.5 | 🔴 | 根节点最大平移。当前从未触发（实测 0.036 m），阈值偏松，未经压力测试。 |
| `grad_clip` | 10.0 | 🟡 | 梯度范数裁剪，防止早期大梯度把解推飞。 |
| `warm_start` | True | 🔵 | 时间映射暖启动。**强烈建议保持开启**，见 §5 实证数据。设 False 仅用于复现对照实验。 |
| `contact_cfg` | None | 🟡 | 接触判据，见 §4。应与提取步态相位时用的配置一致。 |
| `calibrate_ratios` | None | 🟡 | 权重自动定标比例，见 §2。**这是最重要的调参入口**。 |
| `device` | `"cpu"` | — | `"cpu"` / `"cuda"`。 |
| `seed` | 0 | — | 随机种子。当前流程是确定性的（零初值），仅为可复现性保留。 |
| `log_every` | 50 | — | 日志间隔，不影响结果。 |

## 2. 损失权重 — `motionedit/losses.py` 的 `LossWeights`

### 2.1 推荐入口：`calibrate_ratios`

**不建议直接改 `w_prior` / `w_rom` 等绝对值** —— 它们的合适量级依赖于具体动作和参数
组合，手工设定基本无法迁移。默认走自动定标：把每项权重设成"该项在初始点的贡献
占任务项的指定比例"。

```python
solve(..., cfg=SolverConfig(calibrate_ratios={
    "prior": 0.3,     # 越大 → 越贴近原动作风格，但任务目标达成度下降
    "rom":   0.1,     # 初始点恒为 0 无法定标，实际由 rom_growth 退火生效
    "smooth":0.1,     # 越大 → 越平滑，但可能磨掉正常的动作细节
    "contact":0.4,    # 越大 → 脚越"钉"在地上
}))
```

状态：🟡 这四个比例是经验值。`contact` 取最高是因为脚滑是实测中最易出现、视觉上
最刺眼的失败模式。**若要做消融实验，这四个数是首选对象。**

### 2.2 任务项内部配比

| 名称 | 默认 | 状态 | 说明 |
|---|---|---|---|
| `w_knee` | 1.0 | 🟡 | 膝屈曲 |
| `w_trunk` | 1.0 | 🟡 | 躯干前倾 |
| `w_elbow` | 0.5 | 🟡 | 肘屈曲。取一半是因为端托姿势下肘角本就变化很小，信息量低。 |
| `w_root` | 300.0 | 🟡 | **量纲换算**：位置项单位是 m²，角度项是 deg²，两者差约两个量级。300 ≈ (17°/m)²，即"偏 1 米 ≈ 偏 17 度"。这个换算率是主观的，可调。 |

### 2.3 权重退火

| 名称 | 默认 | 状态 | 说明 |
|---|---|---|---|
| `prior_decay` | 0.1 | 🟡 | `w_prior(k) = w_prior · 0.1^k`，即末期降到初期的 1/10。早期紧贴 A_ref 提供好初值，后期放开让任务项充分表达。 |
| `rom_growth` | 20.0 | 🟡 | `w_rom(k) = w_rom · 20^k`。早期允许探索、不被限位卡死，后期强制回到合法区。**若最终解出现 ROM 越界告警，优先调大这个数。** |

> 退火形式固定为指数型，未做可配置。若要换成余弦/线性，改 `LossWeights.at()` 一个方法即可。

### 2.4 contact 项内部三分量

| 名称 | 默认 | 状态 | 说明 |
|---|---|---|---|
| `contact_penetration` | 1.0 | 🟡 | 穿地惩罚（单边 relu，抬脚不罚） |
| `contact_slip` | 1.0 | 🟡 | 支撑帧上的水平速度惩罚 |
| `contact_drift` | 0.5 | 🟡 | 支撑帧上相对参考位置的漂移惩罚。**这一项不可去掉**：只罚速度的话，整只脚匀速平移能"合法"地滑过去。 |

## 3. 关节活动度 — `motionedit/rom.py`

| 名称 | 位置 | 状态 | 说明 |
|---|---|---|---|
| `ROM_LIMITS` | 模块级 dict | 🔵 | 16 个关节的 swing/twist 上限。由解剖学 ROM 归并而来，并在 A_ref 上验证过零越界。**改动需重新验证参考动作惩罚仍为 0。** |
| `Hand` 的 twist 上限 | 90°（非 30°） | 🔵 | 该绑定把前臂旋前/旋后分配到了 Hand 骨骼的 twist 通道，故按前臂范围而非腕关节范围设定。**这是实测结论，不要"修正"回 30°。** |
| 惩罚形式 | `relu(θ-limit)²` | 🟡 | 二次软惩罚。可改为一次（更"硬"）或 softplus（更平滑）。 |

自定义用法：

```python
from motionedit.rom import ROM_LIMITS, SwingTwistLimit, build_rom_penalty
limits = dict(ROM_LIMITS)
limits["mixamorig:LeftLeg"] = SwingTwistLimit(max_swing=120.0, max_twist=20.0)
rom = build_rom_penalty(skel, limits)
solve(..., rom=rom)
```

## 4. 步态与接触判据 — `motionedit/phase.py` 的 `ContactConfig`

| 名称 | 默认 | 状态 | 说明 |
|---|---|---|---|
| `height_margin` | 0.035 m | 🟡 | 高于序列最低点多少米以内算"贴地"。**对步频识别最敏感的一个参数**，换动作数据时优先检查。 |
| `speed_threshold` | 0.55 m/s | 🟡 | 水平速度上限。与 `height_margin` 是"与"关系。 |
| `min_contact_frames` | 3 | 🟡 | 短于此长度的接触段视为噪声剔除 |
| `min_gap_frames` | 2 | 🟡 | 短于此长度的腾空段视为噪声填补 |

> 这套阈值在 A_ref 上能稳定识别出 34 帧的步态周期。**换用其他动作序列时务必先跑
> `inspect_reference.py` 确认 `相位识别成功 = True` 且周期数值合理。**

## 5. 目标曲线 — `motionedit/targets.py`

| 名称 | 位置 | 状态 | 说明 |
|---|---|---|---|
| 双支撑扰动强度 | `build_time_map` 中 `a = 3.0 * offset` | 🟡 | 系数 3.0 决定 `double_support_offset` 的实际作用强度。>0.95 时会被收紧以保证时间映射单调（时间不能倒流）。 |
| 扰动函数形式 | `φ - a·sin(4πφ)/4π` | 🟡 | 选它是因为满足：处处可微、`|a|<1` 时严格单调、每周期积分为 0（不改变周期总长，只改周期内部疏密）。 |
| 屈曲角下界钳位 | `clamp_min(0.0)` | 🔵 | 屈曲角是非负量（0° = 完全伸直），负偏置可能压到负数。 |
| 四元数插值 | nlerp（非 slerp） | 🔵 | 24fps 下相邻帧夹角通常 < 5°，两者差异可忽略，nlerp 无奇异、无分支、更快。插值前做半球对齐。 |

## 6. 托盘 — `motionedit/tray.py` 的 `TrayConfig`

| 名称 | 默认 | 状态 | 说明 |
|---|---|---|---|
| `palm_offset` | 0.0 m | 🔴 | 沿手部前向的掌心偏置。当前为 0，即托盘中心正好在双手中点，**未与真实网格对齐验证过**。 |
| `lift_offset` | 0.02 m | 🔴 | 托盘底面相对手心的抬高量。同上，**需在 Linux 机上渲染出来目视确认。** |
| `max_tilt_deg` | 20.0° | 🟡 | 托盘法线相对世界竖直的最大倾角。防止托盘"翻过来"。 |
| `smooth_window` | 5 帧 | 🟡 | 移动平均窗口，须为奇数。 |

> 🔴 这一组是当前**验证最薄弱**的部分：几何上自洽（托盘中心贴合双手中点误差
> 0.027 m、轨迹平滑），但没有渲染出来看过。第 4 层渲染完成后应优先目视复核。

## 7. 骨骼范围 — `motionedit/skeleton.py`

| 名称 | 默认 | 状态 | 说明 |
|---|---|---|---|
| `CORE_BONES` | 21 根 | 🟡 | 参与优化的骨骼白名单（躯干 + 四肢核心）。其余 44 根（手指、末端占位骨骼）保持参考值不变。**扩大范围会增加自由度与耗时，且手指等骨骼对负重观感贡献很小。** |

```python
custom = [b for b in CORE_BONES if "Hand" not in b]   # 例：冻结手部
loss_fn = MotionLoss(..., dof_mask=skel.dof_mask(custom))
```

## 8. 参数边界 — `motionedit/params.py` 的 `PARAM_BOUNDS`

LLM 输出的 7 个参数的合法区间（软裁剪）。状态 🟡，全部为经验值：

| 参数 | 区间 |
|---|---|
| `knee_flex_scale` | 0.5 ~ 2.0 |
| `trunk_lean_offset` | −15 ~ +40° |
| `cadence_scale` | 0.5 ~ 1.8 |
| `double_support_offset` | −0.10 ~ +0.25 |
| `stride_length_scale` | 0.4 ~ 1.6 |
| `elbow_flex_offset` | −20 ~ +45° |
| `tray_chest_distance_scale` | 0.5 ~ 1.5 |

> 这些边界决定了**外层 agent 的搜索空间**。若发现 LLM 反复把某个参数顶到边界，
> 说明该边界可能限制了最优解，值得放宽。

## 9. 已固定、不建议改动的部分

以下不是"超参数"，而是**经实证确定的设计决策**，改动需要重新验证：

| 内容 | 位置 | 为什么固定 |
|---|---|---|
| swing-twist 而非 ISB 欧拉分解做 ROM | `rom.py` | ISB 方案在 A_ref 上产生 24803 的伪惩罚，最大伪越界 161.9° |
| 任务项在几何角度域比较 | `losses.py` | 同上根因：骨骼局部轴与解剖轴无对应关系 |
| 增量旋转向量参数化 | `solver.py` | 避免四元数单位模长约束干扰优化器 |
| 平滑项用二阶差分 | `losses.py` | 一阶差分会连正常运动一起压掉 |
| `Spine` 骨骼的非零平移须保留 | `motion_io.py` | 数据真实属性（0.0131 m），置零会导致躯干错位 |
| 上向轴 = 世界 Z | 多处 `_UP = 2` | `human_model_up_bone_zup.json` 是 Z-up |
